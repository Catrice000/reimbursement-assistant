# Reimbursement Assistant · 财务报销助手

**v0.2 · 可运行的本地演示。** 员工先自助查询有效制度，再经授权查看本人单据；制度由行政专员维护，单据事实由财务专员核对。

使用 Python 标准库、SQLite 与原生网页，无须安装第三方依赖。没有接入 AI 模型、企业身份系统或外部财务数据源。制度、账号与单据全部为虚构演示数据。

## 快速运行

安装 Python 3.10 或更新版本，在仓库目录执行：

```bash
python server.py
```

浏览器打开 **http://127.0.0.1:8000**。首次启动自动创建 `data/app.db`；后续启动保留修改。已有 v0.1 数据库会自动升级，保留已有制度、单据、授权状态及备注。可通过 `PORT` 修改端口、`APP_DB` 修改数据库路径。

本地地址只用于运行项目的电脑；ChatGPT 内置云浏览器无法直接访问这里的回环地址。本项目尚未部署成线上网站。

## 已完成的业务流程

### 员工工作台

- 制度问答：输入问题、快捷问题、最近查询记录、关键词标记和原文出处。
- 原文检索：只使用已发布且当前有效的制度，显示版本、生效日期、适用范围及完整原文；没有匹配依据时提示补充问题或联系行政。
- 制度资料：按名称/原文搜索、适用范围筛选、阅读原文。
- 本人单据：按编号/名称和状态筛选，查看金额、最新核对备注、更新日期及历史记录。
- 未获授权时展示清晰提示，仍然可以查询制度。

### 行政工作台

- 制度版本列表、有效/草稿/历史状态筛选。
- 新增和编辑草稿，粘贴原文或导入 UTF-8 TXT/Markdown（100 KB以内，原文30000字以内）。文件只在浏览器读取，保存的是文本。
- 制度发布和撤回需确认；同名制度有效期重叠时阻止发布。
- 已发布原文不能直接编辑；修订创建新草稿，保留原版本。
- 查看行政职责范围内最近100条操作记录。

### 财务工作台

- 查看演示单据，按编号/名称、状态筛选。
- 事实核对：状态和备注由财务填写，每次保存追加历史记录。
- 并发版本检查：单据被其他人更新后，旧页面不能覆盖新记录，需刷新重新核对。
- 开通/撤销员工本人单据查询权限，不开放其他人的单据或额外管理权限。
- 查看财务核对与授权操作记录。

### 界面

独立登录页、角色导航、统计摘要、制度卡片、表格筛选、原文与详情弹窗、核对历史时间线、空状态、错误提示、操作中状态及移动端布局。全部资源来自项目自身，无外部字体、CDN或图片依赖。

## 演示路径

1. **员工**：登录小林 → 查询“出差报销需要哪些材料” → 阅读原文 → “我的单据”查看 R-0001 的核对历史。
2. **行政**：切换乔姐 → 新增制度 → 保存草稿 → 编辑/发布 → 切换员工确认新制度可查询。撤回后，新查询不再返回该制度。
3. **财务**：切换周敏 → R-0001“查看/核对” → 改为“待补充材料”，填写缺项 → 保存 → 切回小林查看最新记录。
4. **授权**：周敏在“查询授权”撤销小林权限 → 小林刷新单据查询得到未授权提示；制度查询仍可使用。

## 权限与数据设计

- 后端校验每个请求的身份、角色及员工查询授权，员工列表按登录身份过滤；详情同时验证归属，不能靠输入编号查看他人单据。
- 默认虚构演示员工已经获得查询授权。授权持久化到数据库，撤销后重启不会重新开通。
- 撤销在后续列表/详情读取时生效。已经显示在页面上的内容无法远程收回。
- SQLite 持久化制度版本、单据、授权、核对历史和操作日志；数据目录不提交到 GitHub。
- 密码使用随机盐与 PBKDF2；Cookie 为 HttpOnly / SameSite=Strict；写请求验证 CSRF；失败登录每账号/IP五次后限流一分钟。
- 页面文本转义，发布/核对使用服务器校验，详情访问和写权限均由后端落实。
- 会话保存在进程内，8小时过期，重启需重新登录。默认仅监听回环地址。

## AI 预留位置

`server.py` 的 `retrieve(db, question)` 是检索/回答适配位置，当前返回 `mode: retrieval` 和带制度出处的 `sources`。没有外部 API 调用，也不需要 API key。

未来接入模型时，先检索并过滤当前有效制度，再将证据交给模型生成带引用的答案。单据状态仍通过独立的鉴权接口读取，由财务维护，不让模型推断业务事实。

## 当前限制

- 关键词检索无法理解所有同义表述或复杂条件；适用范围可筛选/展示，暂未按地区、职级自动判定。
- 不支持 PDF/OCR 导入、附件管理、员工创建报销单、真实系统同步、审批流或付款。
- 演示登录、公开演示密码和本地部署仅适合教学/需求验证。正式使用需要企业登录、真实数据接口、HTTPS、安全 Cookie、备份恢复、正式授权流程与部署配置。
- 未进行内置浏览器视觉验收，不把单元/接口测试当作浏览器验收。
- 真实制度、员工信息、单据、数据库和密钥不得提交到公开仓库。
