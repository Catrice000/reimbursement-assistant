# Reimbursement Assistant · 财务报销助手

一个可运行的本地业务演示，使用 Python 标准库、SQLite 和原生网页，无须安装第三方依赖。未接入 AI 或外部财务系统。

## 运行

需要 Python 3.10+（系统需提供 Asia/Shanghai 时区数据）。

```bash
python server.py
```

打开 http://127.0.0.1:8000 。首次启动自动创建 `data/app.db` 并填入**虚构演示数据**。可用 `PORT` 修改端口、`APP_DB` 修改数据库路径。

## 功能与边界

- 员工先查有效制度：只检索已发布、当前日期在有效期内的制度，返回原文条款、版本、日期、适用范围及完整原文。
- 当前使用关键词匹配，不具备模型语义理解、综合推理能力。无匹配时提示联系行政；适用范围仅展示，暂不自动判断地区或员工类别。
- 制度由行政专员维护；修订创建新草稿，不覆盖已发布原文；同名版本有效期重叠时阻止发布。暂只支持粘贴文本，不支持 PDF/OCR 导入。
- 员工单据查询经服务端身份校验，数据库查询按登录账号过滤；行政无单据访问权；员工不能更新核对事实。
- 事务事实仍由财务专员核对。每次更改保存核对人、时间和审计记录；不会发起审批或付款。
- 只有虚构演示单据；未实现员工提交报销单、真实系统同步、附件管理和审批流。

## AI 接口预留

`server.py` 的 `retrieve(db, question)` 是检索/回答适配位置。当前固定返回 `mode: retrieval` 和带出处的 `sources`，前端明确提示原文检索。未来接入模型时，先取得有效制度证据，再让模型基于证据回答；单据状态仍通过独立、受权限保护的接口读取，不由模型生成。此版本无 API key 配置和外部 API 调用。

## 验证

```bash
python -m unittest discover -s tests -v
```

测试覆盖制度有效期、草稿/撤回过滤、陌生问题、员工单据隔离、角色写权限、修订留存及 HTTP 登录/CSRF/越权边界。

## 使用限制

这是本地演示，默认仅监听回环地址。演示账号及密码是公开的，不得用于真实业务。会话保存在进程内，8小时过期，重启需重新登录。密码使用随机盐与 PBKDF2；写接口检查 CSRF token；页面对用户内容转义。

投入真实使用前需替换演示账号为企业身份认证、接入真实财务数据源、设置员工查询授权范围、HTTPS、安全 Cookie、登录限流、审计持久化与备份恢复机制。不得把真实制度、员工数据、单据或密钥提交到公开仓库。SQLite 数据目录已忽略。
